# data/

The pipeline's working directory for generated artifacts. Unlike most Python
projects, `data/` is **intentionally tracked in git, not globally ignored** — the
preference dataset this project produces is the deliverable (spec §13). See the root
[`.gitignore`](../.gitignore) for the exact policy: only `data/raw/`'s contents are
excluded (third-party datasets fetched in a later step are re-downloadable and not
worth committing), everything else under `data/` is tracked normally.

As of Step 1, no pipeline stage has run yet, so every subdirectory below is empty
except for a `.gitkeep` placeholder that keeps it present in git. They correspond
1:1 to the `paths.*` entries in [`config.yaml`](../config.yaml) and the `Paths`
dataclass in [`src/python_dpo/config.py`](../src/python_dpo/config.py), whose
`ensure_exists()` method can recreate this exact structure from scratch.

## Subdirectories

### `raw/`

Third-party datasets (e.g. HumanEval, MBPP) downloaded in a later step. Contents are
git-ignored (`data/raw/*` in `.gitignore`) since they're re-downloadable; only the
directory structure (via `.gitkeep`) is kept.

### `problems/`

Curated Python programming problems that will serve as input to candidate generation.
Not yet populated — problem sourcing is a later pipeline step.

### `candidates/`

Candidate solutions generated by the Qwen Coder model for each problem. Not yet
populated — candidate generation is a later pipeline step, and no model inference
code exists yet.

### `evaluations/`

Results of running candidates through the (future) Docker sandbox and pytest
evaluation. Not yet populated — no execution or evaluation code exists yet (and per
`CLAUDE.md`, none will until it can run inside an isolated sandbox).

### `preferences/`

Preference pairs (chosen vs. rejected candidates) derived from evaluation results —
the DPO training input. Not yet populated — preference-pair generation is a later
step.

### `reports/`

Summaries and reports produced by pipeline runs (e.g. per-run statistics). Not yet
populated — no pipeline run exists yet.

## Files

### `.gitkeep` (in each subdirectory)

Zero-byte marker files. Git doesn't track empty directories, so each subdirectory
carries one to stay present in the repository until real content is generated.
